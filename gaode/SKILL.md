# 高德周边探索（周边去哪儿）

## 何时使用

用户给出一个位置（通常带坐标）和一句需求，想知道"附近有什么值得去的地方"。典型输入：

> 我在杭州某地铁站（120.15, 30.27），想找一家咖啡馆，步行不超过 15 分钟，推荐最多 3 家，优先近一点的。

本 Skill 负责完成完整链路：**理解需求 → 查高德地点 → 查步行路线 → 筛选推荐 → 输出答案**。单轮任务即可完成，不要停下来反问用户；不需要做定位（起点坐标由用户或评测平台给出），不需要长期记忆，也不需要接入 seekdb 或 PowerMem。

## 可用工具（高德 MCP Server）

按功能选择工具。**工具名以运行环境实际提供的为准**；若名字不同，按功能描述选择等价工具（高德官方工具名见下表）。

| 功能 | 首选工具名 | 入参 | 关键返回 |
| --- | --- | --- | --- |
| 周边搜索（主用） | `maps_around_search` | `keywords`（类型关键词）、`location`（起点 经度,纬度）、`radius`（米，可选） | `pois[]`：名称、`location`、`address`、`type`、`business_area`（商圈，若有） |
| 关键词搜索（补充） | `maps_text_search` | `keywords`、`city`（可选） | `pois[]` |
| 步行路径规划（必须用） | `maps_direction_walking` | `origin`（经度,纬度）、`destination`（经度,纬度） | `paths[0].distance`（米）、`paths[0].duration`（秒） |
| POI 详情（补地址/类型） | `maps_search_detail` | `id`（poi id） | `address`、`type`、`location` |
| 地理编码（仅缺坐标时） | `maps_geo` | `address`、`city`（可选） | `location` |

坐标一律是高德 **GCJ-02，经度在前（lng,lat）**，不要调换顺序。若路径信息嵌套在 `route.paths[0]` 下，取该处的 `distance` / `duration`；单位为米 / 秒。

> **关于"距离测量"类工具**：工具目录里如果还有 `maps_distance` 之类的工具，它的默认模式可能是驾车或直线，**不得**拿它当步行距离/时间来源。只有在显式指定步行模式时才可用于粗筛，而且它的数值不能直接出现在答案里。答案里的步行距离和时间只能来自 `maps_direction_walking`。

## 硬性规则（违反会直接失分）

1. **只写高德返回的数据。** 推荐的每个地点必须出现在本次高德搜索结果里；名称、地址照抄返回结果，不改写、不补充、不凭记忆添加。
2. **步行距离与时间必须来自步行路线查询。** 用 `maps_direction_walking` 的 `paths[0].distance` / `paths[0].duration`。禁止用直线距离、驾车时间、公交时间或地图上的经验估算替代。
3. **不超时间上限。** 步行时间超过用户给定上限的地点一律不进推荐列表，也不放进"稍远一些"之类的补充区。说明里可以写"已排除超出 X 分钟的地点"，但不要列出这些地点。
4. **最多 3 条。** 用户要求更多也按 3 条封顶，并说明"按要求最多推荐 3 个"。
5. **不足就如实说。** 符合条件的地点少于用户要求的数量时，可以少推荐，但必须在"说明"里写清原因，并给出可放宽条件的建议。
6. **无依据的信息标"未核实"。** 安静程度、排队情况、营业状态、是否需要预约、评分、人均消费、是否有座位等，只要高德返回里没有依据，一律写"未核实"，绝不编造。
7. **失败就如实说。** 工具报错或无结果时，说明失败原因或"在给定范围内未找到"，不要用印象里的店名、地址凑数。
8. **不写密钥。** 本文件不含也不需要任何 API Key。

## 执行步骤

### 第 1 步：解析需求

| 项 | 从用户输入抽取 | 缺省 |
| --- | --- | --- |
| 起点坐标 | 用户给定的 lng,lat | 无坐标见"异常处理" |
| 城市 | 杭州 / 上海 … | 有坐标即可省略 |
| 地点类型 | 咖啡馆 / 餐厅 / 公园 / 书店 / 药店 / 健身房 … | 未指明类型时用宽泛关键词（如"餐厅""商场"），并在说明里写明这个假设，**不要停下来反问** |
| 步行时间上限 | "步行不超过 15 分钟" → 15 分钟 | **15 分钟**（答案里注明这是默认假设） |
| 推荐数量 | "推荐最多 3 家" → 3 | **3** |
| 偏好 | "优先近一点" / "离我最近" | 按步行时间由近到远 |

把用户口语映射成高德关键词："咖啡馆" → `咖啡`、`咖啡馆`；"吃点东西/吃饭" → `餐厅`；"遛弯/散步" → `公园`；"买药" → `药店`；"看书" → `书店`。先用最贴近的那个词。

### 第 2 步：查询候选地点

- 主用周边搜索：`maps_around_search(keywords=类型关键词, location=起点坐标, radius=R)`。
- **半径 R 怎么定**：步行速度按约 80 米/分钟估算，`R ≈ 上限分钟 × 80 × 1.5`，向上取整到 100 的倍数，最小 800 米，最大 5000 米。例：15 分钟 → R = 1800 米。（80 米/分钟只用来估搜索半径，绝不能作为答案里的步行时间。）
- **候选太少（0～2 条）时依次尝试**：① 换近义关键词（`咖啡` → `咖啡馆` → `咖啡茶饮`）；② 用 `maps_text_search(keywords=…, city=城市)` 补充，再按 POI 坐标与起点的直线距离筛（不要用它返回的 `distance` 字段，那个不是相对起点的距离）；③ 扩大 radius 到上限再试。
- **过滤**：保留 `type` / `name` 与用户要的类型相符的 POI；去掉同名同址的重复项（poi id 相同或坐标几乎相同）。
- 候选按起止坐标算出的直线距离由近到远排序。**直线距离只用来挑"要送去问路线"的候选，绝不能写进答案。**

### 第 3 步：查步行路线

对最近的 **6～8 个**候选逐个调用 `maps_direction_walking(origin=起点坐标, destination=候选坐标)`：

- 取 `paths[0].distance`（米）与 `paths[0].duration`（秒）。
- 换算展示：距离取整到米（≥1000 米写成"约 1.2 公里"），时间 = `duration / 60` 向上取整到整分钟。
- 某个候选路线查询失败时，先重试 1 次；仍失败就跳过它，用剩下的候选，**不要**给它编一个距离/时间。
- 候选总数不足 6～8 个时全部查询。
- **不要因为"只查了一批"就断定结果不足**：如果查完这批后达标数量还没到 N，继续对下一批候选查路线，直到取满 N 或候选用尽。说明里写清"已查询 X 个候选，其中 Y 个在步行上限内"。

### 第 4 步：筛选与排序

1. **硬过滤**：只保留步行时间 ≤ 用户上限的地点，以路线查询结果为准。
2. **排序**：
   - "优先近一点 / 最近的" → 按步行时间升序；
   - "优先评分 / 口碑好 / 最热门" → 仅当工具返回里确有评分或排行类字段时才据此排序；否则仍按步行时间升序，并在说明里写"评分/口碑信息未核实，未参与排序"；
   - 其余情况默认按步行时间升序。
3. 取前 N（默认 3）条。剩余时间达标但未被选中的候选，不要顺带补进来；**时间超标的地点也不要放进任何补充区**。
4. **数量不足时**：少推荐 + 说明原因（例如"在 15 分钟步行范围内只找到 2 家符合条件的咖啡馆"）+ 放宽建议（放宽到 20 分钟 / 扩大半径 / 换关键词）。

### 第 5 步：生成答案

用用户提问的语言回答。固定结构：**一句话结论 → 推荐表 → 说明**。

结论句式（数量与上限按用户实际需求替换）：

> 按"优先近一点"为你推荐 N 家步行可达的 <类型>，均在 <上限> 分钟内。

推荐表（下面每个占位符都必须替换成本次工具调用的真实结果，不允许照抄任何示例数值或自行估算）：

| # | 地点名称 | 地址 | 步行距离 | 步行时间 | 推荐理由 |
| --- | --- | --- | --- | --- | --- |
| 1 | <poi.name> | <poi.address> | 约 <distance 换算后的米数> | 约 <duration 换算后的分钟数> | <一句基于距离/时间/类型的理由> |
| 2 | <poi.name> | <poi.address> | 约 <…> | 约 <…> | <…> |

**说明**

- 用了默认上限时才写："你未指定步行时间上限，默认按 15 分钟计。"
- 数量不足时："在 15 分钟步行范围内只找到 2 家符合条件的咖啡馆（已查询 X 个候选），可放宽到 20 分钟或换个关键词再试。"
- 未核实项："营业状态、排队情况、安静程度未核实（高德返回中无此信息）。"
- 工具失败时："高德地点搜索失败（错误信息），本次无法给出可信推荐，建议稍后重试。"

推荐理由必须落在高德数据上（距离、时间、类型、商圈），一句话，不写没有依据的主观判断。

## 异常处理

| 情况 | 处理 |
| --- | --- |
| 只有地名、没有坐标 | 用 `maps_geo(address=地名, city=城市)` 取坐标；取不到就请用户提供"城市 + 起点名称或坐标"，不要猜。 |
| 周边搜索 0 结果 | 换关键词 → 用 `maps_text_search` 补查 → 扩大半径；仍无果则如实说"在 X 附近的搜索范围内未找到符合条件的 <类型>"，并建议放宽条件。 |
| 步行路线查询报错 | 同一候选重试 1 次；仍失败就跳过该候选，其余照常推荐，并在说明里注明"个别候选的步行路线未能查询到"。 |
| 全部候选都超时 | 如实说"没有找到步行 X 分钟内可达的 <类型>"并给出放宽建议，**不列超时地点**。 |
| 工具整体不可用 | 同一工具重试 1 次；仍失败则如实报告工具名与错误信息，建议稍后重试；绝不凭印象编造地点。 |

## 常见说法到动作的映射

| 用户说法 | 动作 |
| --- | --- |
| "随便 / 都行 / 没要求" | 用默认：3 个、15 分钟、按步行时间升序 |
| "就近一点 / 最近 / 近的优先" | 按步行时间升序；理由里点明"最近的一家" |
| "环境好 / 安静 / 人少" | 不许编造。高德返回没有相关字段时，在该条理由里写"环境与客流情况未核实" |
| "性价比高 / 便宜" | 同上。没有人均消费就写"价格未核实" |
| "营业中 / 现在还开着吗" | 不许编造，写"营业状态未核实（建议出发前在地图上确认）" |
| "多点几个 / 推荐 5 个" | 最多 3 个，并说明"按要求最多推荐 3 个" |
| "两个地方之间怎么走" | 本 Skill 只做周边推荐；用户问路线细节时用步行路径规划工具直接给出路线，不要凑成多站行程 |

## 输出前自检

- [ ] 每个推荐地点都能在本次高德搜索结果中找到，名称与地址与返回一致
- [ ] 每个距离与时间都来自本次 `maps_direction_walking` 结果，单位换算正确，没有任何示例数字残留
- [ ] 不超过 3 条，且全部在步行时间上限内
- [ ] 排序与路线数据一致（"优先近一点"时第一条就是步行最短的）
- [ ] 没有任何编造信息，需要的地方标了"未核实"
- [ ] 数量不足、查询失败或使用了默认上限，都已在"说明"里写明
- [ ] 没有出现坐标、POI id、原始 JSON 或工具调用日志等噪声
