# 验证样例

以下样例用于验收「谜海拾贝」的可运行性、功能完整性与技术结合。评审可按此逐步体验。

> 前置：seekdb 已启动、桥接服务已运行、Dify 已导入应用并配置好 Ollama（deepseek-r1:8b）。

---

## 1. 基础验收：可运行性

| 步骤 | 操作 | 期望结果 |
| --- | --- | --- |
| 1.1 | 访问 `GET http://localhost:3001/api/health` | 返回 `database.connected: true`，`collections` 包含 `stepfun_riddles` |
| 1.2 | 访问 `GET http://localhost:3001/api/stats` | 返回 `count` ≈ 44（24 谜语 + 20 冷知识） |
| 1.3 | 打开 Dify 应用并发送“你好” | 收到友好的自我介绍与功能提示 |

---

## 2. 功能完整性

### 2.1 出谜语（seekdb 检索）

| 步骤 | 输入 | 期望结果 |
| --- | --- | --- |
| 2.1.1 | “给我出一个关于动物的谜语” | 返回一条**动物类**谜语的谜面，**不出现谜底**，并鼓励用户猜 |

### 2.2 猜答案（会话上下文校验）

| 步骤 | 输入 | 期望结果 |

| 2.2.1 | 接着上一题，输入“是大熊猫” | 若与上题谜底一致则恭喜并解释；否则鼓励再试、**不直接给答案** |

| 步骤 | 输入 | 期望结果 |

| 2.4.2 | “讲一个关于动物的冷知识” | 返回知识库中的动物冷知识（如章鱼三颗心脏、蜂鸟倒飞等） |

### 2.5 闲聊兜底

| 步骤 | 输入 | 期望结果 |
| --- | --- | --- |
| 2.5.1 | “你能做什么？” | 返回功能介绍（出谜语 / 猜谜 / 冷知识） |

## 3. 技术结合核验

评审需确认 seekdb 在应用中的**实际作用**：

1. **检索路径可观测**：向桥接服务发送 `POST /api/retrieve`，请求体：
   ```json
   { "query": "关于动物的谜语", "category": "riddle", "n": 3 }
   ```
   返回结果中 `mode: "hybrid"`，且 `results[].metadata.type` 为 `riddle`。

2. **混合检索生效**：返回的 `document` 应包含与“动物”语义或关键词相关的内容（`searchMs` 字段体现真实数据库查询耗时）。

3. **数据确实入库**：`docker exec stepfun-seekdb mysql -uroot -h127.0.0.1 -P2881 -e "SELECT count(*) FROM stepfun_kb.stepfun_riddles"`（或通过 `/api/stats`）可看到数据量。
